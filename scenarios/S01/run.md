# S01 - A new service is exposed by adding one file

Fictitious company: Cartiera Valdora S.p.A. - synthetic data only. **Failure reproduced.** Four services are routed; a fifth (tracking) is declared in the topology but has no route. One file, input/new/tracking.yaml, is added under routes/. **Pass criterion.** The table is accepted before and after; the diff is exactly 1 entry added, 0 removed, 0 changed; every pre-existing file is byte-identical; the new public host resolves to tracking:3000 and is not served on the admin entrypoint. **Lesson.** Exposing a service is one reviewable file; the diff of the route table is the review. Run it from this folder with `python check.py` (exit code 0 means the scenario passed; the checker needs no argument, no environment variable and no network) and read the detail in `build/scenarios/S01/result.json`.
