# S04 - The healthcheck watches the process, the route answers 404

Fictitious company: Cartiera Valdora S.p.A. - synthetic data only. **Failure reproduced.** At 06:41:30Z the status service stops serving its root path while its process stays up. Its declared healthcheck is of kind process, so it keeps reporting healthy. **Pass criterion.** The end-to-end probe declares the failure at the second consecutive failing beat (first 06:42:00Z, declared 06:43:00Z): verdict FAILED, exit code 3, finding on topology.yaml / status, the console never prints RUN OK, and the rendered postmortem equals expected/postmortem.md and has a timeline and an evidence section. **Lesson.** A healthcheck that probes the process proves the process; only a request through the route proves the service. Run it from this folder with `python check.py` (exit code 0 means the scenario passed; the checker needs no argument, no environment variable and no network) and read the detail in `build/scenarios/S04/result.json`.
